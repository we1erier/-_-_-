# Анализ бизнес-процесса

1. В процессе задействовано 3 дорожки. Самым трудоемким и критичным по времени является переход между программной системой анализа и базой данных при записи больших объемов информации.
2. Параллельные ветки (fork/join) применены для одновременной записи в БД и отправки уведомлений. Дальнейшее распараллеливание ограничено зависимостью формирования итогового отчета от успешности записи.
3. Внешним прерывающим событием является таймаут ожидания ответа от внешних источников.
4. Для автоматизированных IT-процессов, тесно связанных с программным кодом и компонентами системы, UML Activity подходит лучше, чем BPMN.
