# Сравнение подходов моделирования

1. **Сколько раз название контейнера «Backend API» встречается в puml-файлах и сколько в workspace.dsl?**
   В PlantUML-файлах название дублируется на каждом уровне абстракции вручную. В Structurizr DSL контейнер описывается ровно один раз в блоке модели, а на диаграммах лишь переиспользуется. При переименовании в DSL достаточно изменить одну строку.

2. **Что умеет C4-PlantUML, чего не умеет Structurizr DSL, и наоборот?**
   - *C4-PlantUML* предоставляет тонкий визуальный контроль над отрисовкой, стилями и связями.
   - *Structurizr DSL* обеспечивает единый источник правки (Single Source of Truth) всей архитектуры, исключая рассинхронизацию между уровнями.

3. **Какой из четырёх уровней С4 оказался для вашей системы бесполезен и почему?**
   Уровень 4 (Code) избыточен для макро-архитектурного описания сервиса доставки, так как дублирует диаграмму классов из ПР1.

4. **Диаграмма компонентов UML и C4 Level 3 — в чём разница? Что вы бы выбрали?**
   UML-диаграмма компонентов отображает физические файлы и модули реализации, тогда как C4 Level 3 показывает логические строительные блоки сервиса. Для проектирования бэкенда на FastAPI удобнее C4 Level 3.

5. **Нужна ли диаграмма развёртывания UML вашей системе?**
   Да, диаграмма развёртывания необходима, так как компоненты сервиса доставки распределяются по контейнерам Docker / Kubernetes с фиксированными сетевыми протоколами (HTTPS/443, AMQP/5672, PostgreSQL/5432).
