# ADR-0003. Асинхронная обработка возвратов и компенсаций через шину событий

**Дата:** 2026-09-12  
**Статус:** принято  

## Контекст
В случае отмены заказа рестораном или клиентом после успешной оплаты требуется запустить процесс возврата средств через платежный шлюз и начисления компенсационных бонусов. Поскольку внешний платежный шлюз может отвечать с задержкой или быть временно недоступен, процесс не должен блокировать основной поток API.

## Рассмотренные варианты
1. **Синхронный вызов API платежного шлюза** прямо в потоке HTTP-запроса отмены от клиента.
2. **Асинхронная обработка (Паттерн Saga / Очередь событий):** при отмене публикуется событие `OrderCancelled` в брокер сообщений (RabbitMQ), после чего фоновый сервис надежно выполняет запросы на возврат средств с механизмом повторов (retries).

## Решение
Вариант 2 (Асинхронная обработка через шину событий).

## Последствия
**Плюсы:** Повышение отказоустойчивости системы, отсутствие зависаний пользовательского интерфейса при медленной работе платежного шлюза.  
**Минусы:** Переход к принципам ивенту-ориентированной архитектуры (Event-Driven), сложность отслеживания сквозных ошибок (требуется логирование ID транзакций).  
**Что станет неверным, если решение пересмотреть:** Схема контейнеров C4 (наличие брокера сообщений RabbitMQ) и диаграмма последовательности отмены заказа.
